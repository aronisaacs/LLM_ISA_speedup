Per-block KV formats

Should every 4-token block of the KV cache pick its own storage format, instead of one fixed format per layer? Stage A answers that offline, on the real keys and values of the model, before any accuracy runs.

Data: commits 859b9f1 (pair/quad C-Eval study) and 17a169c (Stage A). 16 WikiText chunks of 2,048 tokens, all 32 layers, 8 KV heads, head dimension 128, 16-bit values.

Where this comes from

The C-Eval cliff at 40%

The previous study let each layer pick one format: pairs (two tokens merged, one shared residual) or quads (four tokens merged, a residual per token). Up to 30% saving every variant stayed within noise of the dense model. At 40% pairs-only collapsed, and even the per-layer pair/quad mix lost 6 points when keys and values were both compressed. Plain vector compression held up better there.

What Stage A tested

A menu of fixed-size formats, chosen per block

The cache is cut into blocks of 4 consecutive tokens per head. Each block is stored in exactly one format from a short menu, and every format has one fixed size, so hardware only ever sees a few known layouts. A block chooses the format with the smallest error plus a price times its bits; one price per layer sets the layer's budget.

Merged tokens keep their own 16-bit norms. A pair stores one mean direction and one shared signed residual; a quad stores one mean and a residual per token. Residuals keep the largest entries, with a 128-bit position mask. The full menu has 41 formats (6-bit code); the current default has 8 (3-bit code).

1 · Capture (GPU, minutes)

One forward pass over the 16 calibration chunks. Saves every layer's keys and values and the average squared query per key dimension.

2 · Trace error against bits

For every layer, sweep the price from free to expensive and record total error and stored bits, for each menu. Keys use query-weighted error, values squared error.

3 · Compare at equal bits

Against the best single fixed format per layer, exactly what the previous study chose. Every bit counts: norms, masks, format codes and headers.

Stage A measures reconstruction error, not accuracy. No perplexity or C-Eval runs were made.

What to do next

Recommendations

  1. Replace the default menu with the data-picked formats plus one half-dense format, for example D, P32+d, P32+32, P32+0, Q32, Q16, Q8, Q0. Checking it reuses the saved keys and values and needs no GPU.
  2. Turn on index-coded residual positions. It is free from 40% up.
  3. Consider one format per 64-token page as the hardware simplification; it costs about 1–2 points of saving.
  4. Stage B: per-layer sensitivity runs, then C-Eval at 30, 40 and 50% against pairs-only, per-layer pair/quad and vector compression at matched bits.

Limits of this result. Stage A shows that per-block choice lowers reconstruction error by 13–31% (keys) and 12–23% (values) in the 35–50% range. It does not show how much accuracy that buys. The previous study found that single-layer measurements under-predict the damage of compressing all layers together, so only the Stage B accuracy runs can say whether the 40% cliff moves.
